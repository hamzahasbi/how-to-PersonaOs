# API Examples

These examples use a reserved example domain and synthetic values. Replace the
base URL with your authorized deployment. Obtain credentials through that
deployment's supported sign-in or operator provisioning process.

```bash
API_URL='https://api.example.com/api'
PROFILE_HANDLE='example-user'
```

## Health

```bash
curl --fail-with-body "$API_URL/health"
```

## Browser sign-in

Browser clients sign in through the PersonaOS application. The backend sets the
HTTP-only session cookies; application JavaScript does not read their values.
Anonymous login, signup, and password-reset requests require a valid Turnstile
token as described in the API reference.

## Current user from a trusted command-line client

For tools that support bearer authentication, supply an authorized user access
token through your local secret-management process:

```bash
curl --fail-with-body "$API_URL/auth/me" \
  -H "Authorization: Bearer $TOKEN"
```

`TOKEN` is a user access token, never a Supabase service-role key. Do not paste
real tokens into shared examples or enable shell tracing when using credentials.

## Read published content from a server

The following calls require **both** operator-issued API headers. Supply
`PERSONAOS_API_KEY` and `PERSONAOS_API_SECRET` in the trusted server environment.
They are not browser credentials and must not appear in client-side JavaScript
or public environment variables.

```bash
curl --fail-with-body "$API_URL/public/content/$PROFILE_HANDLE/blog" \
  -H "x-personaos-api-key: $PERSONAOS_API_KEY" \
  -H "x-personaos-api-secret: $PERSONAOS_API_SECRET"
```

To request a published document:

```bash
curl --fail-with-body "$API_URL/public/content/$PROFILE_HANDLE/portfolio/default" \
  -H "x-personaos-api-key: $PERSONAOS_API_KEY" \
  -H "x-personaos-api-secret: $PERSONAOS_API_SECRET"
```

The response includes the Markdown text and a temporary `markdownUrl` for clients
that need to fetch the stored file directly. Anyone holding that signed URL can
fetch the file until it expires. Do not include real signed URLs in public logs
or documentation.

## Read the 3D snapshot payload

```bash
curl --fail-with-body "$API_URL/public/world/$PROFILE_HANDLE/3d" \
  -H "x-personaos-api-key: $PERSONAOS_API_KEY" \
  -H "x-personaos-api-secret: $PERSONAOS_API_SECRET"
```

Review the payload before distributing it as a static snapshot. It is published
content, not a credential store. Use the **API Reference** tab for complete
endpoint contracts.
