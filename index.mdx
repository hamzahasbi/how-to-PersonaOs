PersonaOS brings a personal profile, projects, writing, and connected interests
into one publishing platform. These guides describe its content model,
authentication, and REST API.

## Start here

- [Codebase guide](/architecture/codebase-guide): the current system map and where to make changes.
- [Product overview](/overview): the website, dashboard, and 3D experience.
- [Authentication](/auth-model): browser sessions and server-to-server access.
- [Content model](/content-model): authored content and publication state.
- [API examples](/api-examples): requests using placeholder values.
- [Architecture decisions](/architecture-decisions): the design and its trade-offs.

Use the **API Reference** tab for endpoint contracts. The downloadable OpenAPI
specification uses `https://api.example.com/api` as an illustrative base URL
unless the operator configures a public API origin. It is not a hosted demo.

## Access requirements

Public documentation does not grant API access. Account operations require an
authenticated user; published-content endpoints may require operator-issued
server credentials. The `/public/` prefix describes the content's publication
status, not anonymous access.

Use credentials only with the intended PersonaOS deployment. Never put service
keys, session tokens, or signed content URLs into documentation, screenshots,
issue reports, or browser-side bundles.

Use the navigation for product guidance, API examples, and the current architecture. Development and deployment runbooks and progress history stay out of the public site.
